## 每批材料如何处理

1. **先保留原文。** 记录接收日期、作者或说话者、上下文、材料类型与来源位置。用户的投资观点、用户转述别人的观点、真实案例和整理指令分开标注；材料混合时逐段注明。不为了易读而删除限定词、犹豫、重复但含义不同的表达。
2. **再解释含义。** 用长篇文字描述自己理解了什么，引用原句或定位。为重要观点填写长篇框架中的八个维度；缺失项明确未知，不推测成已确认答案。用户原话、外部观点和助手解释各自有标签。
3. **更新概念与关系。** 用户赋予“好生意”“风险”等词的含义写入 C 条目；重要判断写入 B。近似观点先并列比较，再决定是否合并；合并也保留来源、不同条件和旧编号。
4. **处理引述。** 不以记录语录完成任务。展开用户认同或反对的理由、自己的解释、实际决策意义和不适用情形；出处真实性与用户认同程度分别记录。
5. **整理真实案例。** 使用 casebook 保留当时信息、判断与替代选择，再提出条件明确的暂定思维规则。公司结论不是泛化规则，投资结果也不是规则成立的充分证据。
6. **显式登记张力。** 比较新旧观点，在真实出现分歧时记录 T。用户已有 trade-off 处理方式就保留原话；没有就链接 U。助手可提候选解释，但不能擅自消解冲突。
7. **保留状态。** 区分用户立场、助手理解把握、用户对观点的信心、是否已核对以及是否稳定。用户没反对、重复说过、引用了名人，都不等于确认助手的概括或最终规则。
8. **展示这次变化。** 说明新增材料、长篇解释、相关概念、暂定规则、张力与未解问题，列出需要用户核对的少数重要解释。继续已能开展的整理，不要求用户逐条填表或先批准目录结构。

重要补充或观点变化按新材料记录；原文更正保留更正说明，不能静默修改旧原话。助手提出的假想例子只能标为分析工具，不能写进真实 casebook，也不能用来伪装用户的经验。

## 交付方式

先给足够详细的“我目前如何理解你的观点”，再说明哪些地方不确定、与过去观点有什么张力。只在必要处提具体问题，不先把整批材料压成短原则。未得到用户明确稳定性确认前，最终 AGENTS.md 保持未生成状态。

## 记录约定

每份材料文件包含编号、日期、归属、类型、来源位置与原文区。助手分析另放长篇框架或独立分析区，不混进原文。编号方法见 ontology；文件与检查约定见[工作区约定](../workspace-conventions.md)。
