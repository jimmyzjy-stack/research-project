# 从稳定框架提炼最终 AGENTS.md

状态：未来流程，当前不得执行最终提炼。用户在 [M001](materials/M001-2026-10-10-framework-method.md) 明确要求：“只有在 long-form framework 和 investment ontology 足够稳定，并经过我的确认之后，再从中提炼简洁的 AGENTS.md。”

## 何时可以开始

整理材料与修订长篇框架不需要等待这一确认；编写最终 AGENTS.md 则必须满足上述条件。没有固定材料数量或字数门槛，不能因文件看起来完整、用户暂未回复或检查工具通过就声称稳定。

在请用户确认之前，先把可审阅的完整结果做好：

1. 关键概念含义及相互区别有原文支持，不再只是“质量”“长期”等泛化标签。
2. 重要观点的理由、操作含义、证据、边界、信心与问题可以追溯；未确定部分明确展示。
3. 核心张力有用户实际处理方式，或明确保留为未解；不强求所有矛盾消失。
4. 已提供的真实案例得到充分解释；候选泛化规则有适用边界，没有被冒充为已确认规则。
5. 用户能看到哪些理解已核对、哪些仍待核对，以及准备进入最终文件的候选规则。没有真实材料时不创造案例以满足这一条件。

记录用户实际确认的范围、材料和日期。局部表述核对不等于用户确认整体框架稳定；认同某条观点也不等于批准助手的所有解释。

## 最终文件的范围

只保留以下六类内容：

- 几乎所有投资研究都适用的核心目标。
- 必须始终遵守的决策原则。
- epistemic / evidence discipline：认识与证据纪律。
- thesis discipline：建立、更新、证伪与保留判断历史的纪律。
- portfolio / opportunity-cost discipline：组合、可行替代选择与机会成本的纪律。
- 何时调用 Skills 或详细框架文件的简短路由。

详细推理、案例、语录、特定情境规则与文件操作说明留在 framework、casebook 或 Skills，不复制进最终 AGENTS.md。若观点仅适用特定条件，使用准确的路由提示，不能改写成普遍命令。

## 按决策影响选择内容

每条候选规则写出来源 B／C／T 编号、完整含义、适用范围及需要保留的限定条件，并回答：

> 如果删掉它，助手在什么实际情境中可能作出与用户方法明显不同的判断或选择？

用用户提供的案例、边界与取舍检查答案；新设计的假想情境必须标为测试，不冒充历史案例。保留那些确实改变研究路径、证据门槛、判断更新或组合取舍的规则；不能只保留听起来正确、易于认同的短句。

比较完整框架与简洁文件的行为差异：概念是否被混同、条件是否丢失、张力是否被默认解决、机会成本比较是否改变、未确定问题是否被变成硬规则。发现差异就补充必要限定或指向详细文档，不以减少字数为优先目标。

## 发布前的核对

将候选 AGENTS.md、来源映射、保留与不纳入的理由、仍未解决的差异放在用户面前审阅；不把候选稿称为最终版。当前临时 AGENTS.md 的工作区约定不是用户哲学来源，不能直接改名作为最终版。

最终生成后，详细框架仍是可追溯的依据；以后新材料改变核心判断时同步记录变化，并核对是否影响已提炼规则。不要靠旧最终文件拒绝研究新的反例。
