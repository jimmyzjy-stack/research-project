## 2. 立项各部分真正回答什么

以下是必须建立的理解，不要求13个固定标题；可合并叙述，重要部分展开，未知明示。

| 内容 | 真正解决的问题 | 立项合理深度 / 何时再深入 |
| --- | --- | --- |
| Business model | 谁用、谁付费、为何付费、如何收费和兑现收入？ | 解释主要交易/现金链；不先穷尽每种小产品 |
| Industry / value chain | 上下游谁创造/占有价值，替代方案和交易地位是什么？ | 重要环节和利润/议价机制；细分供应商尽调按后续crux |
| Business traits | 需求持续、成本/投入、经济经常性怎样支持未来FCF？ | 已知与未来合理盈利分开；不要求当前报表已释放全部利润 |
| Competitive advantage / moat | 为什么不会被竞争分走，优势在哪个业务/地域/客户成立？ | 具体机制+反例/成立前提；需要实验/访谈的强度验证列初研，不能因未完成深研即否定 |
| TAM / growth | 真正可服务需求与公司可得份额/跑道多大？ | 关键分母、量×价/工时等方向性拆分；management estimate只是假说，复杂终局估计留后续 |
| Competition / share | 对手如何竞争/获客/补贴，份额是否同口径？ | 主要对手和差异、初步官方交叉检查；不为每个小对手写报告 |
| Volume-price drivers | 增长来自人数/使用/真实量、净价/工资、mix、份额还是并购？ | 拆最影响结果的部分，避免重复计数和名义增长当实际量 |
| Profit / FCF drivers | 收入如何转现金，哪些成本/维持/增长支出/资金需求关键？ | 方向性桥接和关键口径；金融公司的信用/监管资本另看，不以会计利润或CFO直接当股东FCF |
| Management / governance / capital allocation | 谁决策、行为/激励/约束和现金去向如何？ | 相关履历、经营与配置记录、红线/风险；不复制履历，不以持股或背景替代行为证据 |
| Valuation snapshot | 当时市场价格对应什么盈利/现金/成长要求？ | 价格/日期/币种/股数/期间、粗略估值与敏感假设；缺数据不造IRR，不先做精细DCF |
| Key risks / unknowns | 什么会使主要FCF减少、延期、缩短或无法估计？ | 优先关键机制，不是罗列所有风险；未核指控不当实锤 |
| Key research questions | 继续研究应具体解决什么，怎样改变决定？ | 从driver map推出问题、证据/来源、初研与条件深研，而非章节改成问号 |
| Reject / Too Hard / Proceed | 现在的研究去留有何依据？ | 明确依据、支持范围、最高价值未知与下一动作；不把Proceed当买入 |

基础覆盖要足以形成business skeleton和有条件的工作理解；不以“问题驱动”为由省掉它。另一方面，不把公司史、全部同业、完美TAM、精确DCF、几十次访谈或季度beat/miss当立项完成条件。若某个基础事实本身能直接决定退出，应先查，不为阶段名称推迟。

## 3. 继续研究的标准与结论粒度

- **Proceed：**有可解释的经济机制/潜在优势/价值机会或认知积累价值；没有已确证使推进不合理的当前红线；关键未知有可行学习路径，继续研究有决策价值。立项可未充分懂到能投资，但必须说清为什么值得进一步懂。
- **Reject：**已有足够依据表明不符合相关质量/治理/机会条件或不值得投入研究；不能由资料少、非compounder或高PE直接推出。区分公司质地否定、当前价格不投和研究资源暂不优先。
- **Too Hard：**命脉级驱动当前难以合理判断，且可行研究不足以使大致FCF可估；不靠高IRR/小仓位填补。说明难在哪、什么可能重开；不是永久宣判。
- **具体补证/观察：**缺重要原件但有明确核实路径，不机械强贴Too Hard；好公司当前资本回报不足可等价格，并保留研究吸引力。

最少结论：阶段判断+理由、置信度依据/资料限制、research与capital attractiveness分别表达、最高价值未知和下一动作。不要求每个文件/小假设Jimmy确认；正式判断/Pool/资本的material变化仍按D1。

写作采用中文、判断前置、用有口径的少量数字支撑机制；事实/作者解释/管理层预测/工作假设分开。关键论断有原件定位和反方条件，不大段复制材料、评分或名人观点。简洁是抓住因果链，不是删除会改变决策的限定。

## 4. 主动Question Generation：先有业务特定driver map

Business understanding → Value-driver map → What must be true? → Uncertainty → Decision relevance → Questions → Evidence → Best source → Research。

没有用户具体问题也应启动。每个重要公司先在research cockpit建立简洁因果图/公式/层级说明：客户需求及可服务范围、公司获取的实际量/使用、净价格/收费、成本及经济利润、维持/增长投入、营运资金/融资/监管资本、配置/稀释和每股股东结果；标明优势持续时间与经营条件。可用“市场量×可得份额”或“活跃客户×使用”，不能两个覆盖同一层的驱动再乘一遍。

按不同业务拆分，不能用同一树代替银行、平台、消费品或数据订阅。每个重要节点标：已有事实、当前工作假设及待验证链接。还没有Base Case就先写工作理解，不编一组增长/概率做出“Base Case已成立”的假象。

对节点逐一问：
1. 当前Base Case/工作理解要成立，必须什么为真？
2. 我们实际不知道什么？
3. 哪个假设对长期FCF/价值最敏感？
4. 哪个最可能错，依据是什么？没有依据不编错的概率。
5. 什么会证伪？
6. 市场似乎相信什么、有什么同期价格/公开叙事依据？没有依据就标未知，不把自己解释当市场共识。
7. 什么现实可得证据能区分解释？

问题尽量包含“业务节点+可变条件/替代解释+可观察结果+决策影响”。“公司有什么护城河/行业趋势/有哪些风险”只能作入口，不是高优先级问题的最终表达。终局规模/份额/成熟利润率、实现速度、真实量/名义价格和必要投入分开检验；不能只问最终有多大而漏掉现金何时到来。

## 5. 优先级与问题→证据计划

至少沿三轴分别说明，不加总分：
- **Decision sensitivity：**答案会怎样改变FCF金额/时间/持续性/可估计性、价值或资本/研究决定？
- **Uncertainty：**假设的证据缺口、冲突、失效可能性/未来不可知在哪里？不是主观自信高就没有不确定。
- **Researchability / expected value of information：**能否获得区分证据，下一单位时间值得花在哪里？难但重要的问题可先做可学性检查，不能只优先容易搜的题，也不能无限研究不可观察的命脉。

每个高优先级问题在逻辑上包含why matters、affected FCF/value driver、belief、uncertainty、strengthen/weaken/falsify、最佳source、公开可答范围、线下必要性；沿用M022的现有/primary/替代来源与信息价值信息，不机械填表。保留当前少数crux；本次历史eval要求5–10题，不是日常工作永久上限。

初研先检验决定能否继续的机制和关键前提；只有它们成立，才对更昂贵的规模、持久性、成熟利润和价值区间投入深研。不是问题重要就全部马上深研。最高战略crux与下一时间的前置核查可以不同，但须解释依赖、信息价值和重排条件，不能仅因某业务叙事最清晰就认定最高价值。资料搜索由问题反向决定，一线brief及时交Jimmy。

循环：研究一轮→已解决/剩余/重开→belief/confidence为何变→新问题→重新选highest-value unknown→下一单位研究时间。已充分解答不重复研究；保留resolved与重开条件，不把每条新闻加成永久待办。

## 6. 临时Independent Research Question Generator

Main+独立research-planning是默认实现；M022已经拆出，本轮强化生成前端，不需要第9个Skill或常驻Question Agent。重要项目可按M023调用临时独立角色：

- 只给立项、必要primary和基础公司/行业事实、观察边界及通用任务；默认不读Main研究计划、最终thesis、conviction或历史参考答案。
- 独立输出driver map、少数具体有序问题及证据/阶段/下一步；先保留原始输出，再由Main比较遗漏、不同因果链和优先级。
- 相同问题只是思路重合，不增加事实confidence；分歧需要解释，不能投票选题。不同列表共享数据仍不是独立证据。
- 不改正式thesis/valuation/portfolio；不替代D4独立Red Team，它的任务是问对问题，而非对既定建议作反方审阅。
- 如已接触计划/答案，标暴露，不宣称blind；新的context与允许列表不等于技术读权限隔离，也不能消除预训练后验知识。

实际协议、Golden资料可用性、首次输出和限制见[历史问题生成评估](../evals/historical-question-generation.md)。原始案例、首次失败和后续纠偏分别保存，不能按答案回改首轮。
