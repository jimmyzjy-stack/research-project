一个案例对应一次有意义的判断或决策过程，而非简单的公司介绍。同一家公司可以有多个不同阶段的案例；公司日常更新仍保存在 `companies/<company_id>/updates/`，案例链接相关记录，不重复维护两套当前 thesis。

有真实材料后才分配后续CASE编号，保留原始M出处和材料是直接记录还是事后摘要的区别。用户没提供的信息就写未知；助手想出的例子不能作为真实案例，也不能用假想成功与失败补全记录。

从案例提取规则时，需要说明：

- 当时信息、约束与可行替代选择是什么，不能使用后来才知道的信息证明当时“本该知道”。
- 判断通过什么机制影响决策；最终结果怎样，过程质量与结果是否一致。
- 哪些经验可能迁移，在哪些条件下不适用，可能有哪些反例或选择偏差。
- 用户认可的经验与助手推断的候选经验分别记录；成功或失败不是自动确认。

候选规则进入[长篇框架](../framework/long-form-investment-framework.md)的 B 条目；相关概念、条件、张力与开放问题链接到[ontology](../investment-ontology.md)。不要仅保存“这家公司该买／不该买”的结论，也不要把一个案例直接升格成普遍原则。
